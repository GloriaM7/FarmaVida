# FarmaVida

**Exercício 12 de Engenharia de Software** · Modelagem de um sistema de e-commerce para farmácia

O trabalho reúne os requisitos, a proposta de interface, o plano de gestão de configuração, a simulação da primeira sprint, os diagramas de projeto e os casos de teste.

## Documentos da entrega

Os materiais das seis etapas serão vinculados nesta tabela quando os arquivos originais forem adicionados ao repositório.

| Etapa | Pasta prevista | Conteúdo |
| --- | --- | --- |
| 01 · Requisitos | `docs/01-requisitos/` | Diagrama de casos de uso em PNG e SVG e script de geração. |
| 02 · Interface | `docs/02-interface/` | Wireframes de cinco telas em PNG e HTML. |
| 03 · Gestão de Configuração de Software | `docs/03-gcs/` | Plano de gestão de configuração e regras de versionamento. |
| 04 · Scrum | `docs/04-scrum/` | Backlog da Sprint 1, dados em CSV e gráfico burndown. |
| 05 · Projeto | `docs/05-projeto/` | Diagramas de classes, sequência e estados em Mermaid, PNG e SVG. |
| 06 · Teste | `docs/06-teste/` | Casos de teste em CSV. |

O documento consolidado está previsto em `docs/Exercicio12-FarmaVida.docx`.

## Gestão de configuração

- `main` é a branch de entrega, `develop` é a de integração e `feature/<nome>` identifica o trabalho de cada história.
- As alterações entram em `develop` por pull request revisado por outro integrante.
- As entregas usam tags no formato `vMAIOR.MENOR.CORREÇÃO`, como `v1.0.0`.
- Os prefixos de commit previstos são `docs:`, `feat:` e `fix:`. Defeitos e pedidos de mudança são registrados como issues.
